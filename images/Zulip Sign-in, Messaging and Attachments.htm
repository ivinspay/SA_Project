Interaction: Administrative account and role changes

1. Potential Data Repudiation by 1.0 nginx Front-End  [State: Mitigation Implemented]  [Priority: Medium] 

Category:Repudiation
Description:1.0 nginx Front-End claims that it did not receive data from a source outside the trust boundary. Consider using logging or auditing to record the source, time, and summary of the received data.
Justification:The nginx access log records the client IP, time, HTTP method, URL and response status. When an admin changes a role, Zulip also records who made the change, whose role changed, and the old and new roles.

2. Potential Process Crash or Stop for 1.0 nginx Front-End  [State: Mitigation Implemented]  [Priority: Medium] 

Category:Denial Of Service
Description:1.0 nginx Front-End crashes, halts, stops or runs slowly; in all cases violating an availability metric.
Justification:Zulip limits connections per nginx worker and the size of a request. nginx also closes idle keep-alive connections. That helps it keep serving other requests when traffic is heavy.

3. Data Flow Administrative account and role changes Is Potentially Interrupted  [State: Needs Investigation]  [Priority: Medium] 

Category:Denial Of Service
Description:An external agent interrupts data flowing across a trust boundary in either direction.
Justification:If the connection drops during an admin change, show that the result is unknown and let the admin check the account. Check how long nginx waits before it frees the connection.

4. Elevation Using Impersonation  [State: Mitigation Implemented]  [Priority: High] 

Category:Elevation Of Privilege
Description:1.0 nginx Front-End may be able to impersonate the context of Organization Administrator in order to gain additional privilege.
Justification:Django uses the signed-in account to check who is making the change. The account needs the right permissions in that organization, and only an owner can give or take away the owner role.

5. 1.0 nginx Front-End May be Subject to Elevation of Privilege Using Remote Code Execution  [State: Needs Investigation]  [Priority: High] 

Category:Elevation Of Privilege
Description:Organization Administrator may be able to remotely execute code for 1.0 nginx Front-End.
Justification:Make sure nginx and its modules are up to date and that its workers only have access to the files and services they need.

6. Elevation by Changing the Execution Flow in 1.0 nginx Front-End  [State: Needs Investigation]  [Priority: Medium] 

Category:Elevation Of Privilege
Description:An attacker may pass data into 1.0 nginx Front-End in order to change the flow of program execution within 1.0 nginx Front-End to the attacker's choosing.
Justification:Check that nginx and Django read the request path the same way. Reject an unsupported method or an oversized request before it reaches the account-change code.

Category:Tampering

Consider if the function could work with less access to memory, such as passing data rather than pointers. Copy in data provided, and then validate it.
Justification:Django sends the response back to nginx through a local socket. The two programs pass data back and forth without sharing memory on this connection.

11. Replay Attacks  [State: Mitigation Implemented]  [Priority: Medium] 

Category:Tampering
Description:Packets or messages without sequence numbers or timestamps can be captured and replayed in a wide variety of ways. Implement or utilize an existing communication protocol that supports anti-replay techniques (investigate sequence numbers before timers) and strong integrity.
Justification:Django sends its reply to nginx over the same local connection. Zulip limits access to the socket, so the reply is harder to capture and send again.

12. Collision Attacks  [State: Not Applicable]  [Priority: Low]

Justification:Django sends the reply back to nginx through a local socket. There’s no packet reassembly step in this flow.

21. Potential SQL Injection Vulnerability for PostgreSQL  [State: Needs Investigation]  [Priority: High] 

Category:Tampering
Description:SQL injection is an attack in which malicious code is inserted into strings that are later passed to an instance of SQL Server for parsing and execution. Any procedure that constructs SQL statements should be reviewed for injection vulnerabilities because SQL Server will execute all syntactically valid queries that it receives. Even parameterized data can be manipulated by a skilled and determined attacker.
Justification:Zulip uses parameterized ORM queries on the reviewed role and group changes. Check the message and permission queries on this wider flow too, especially any that use raw SQL.

25. Insufficient Auditing  [State: Mitigation Implemented]  [Priority: High]
